# P16 시가 확정 후(09:37) 종가 방향 재예측

**결론: 채택 조건을 충족한다. 그러나 이것은 더 나은 모델이 아니라 늦은 정보 시점이다.**
09:00 시가가 확정된 뒤 같은 타깃(전일 종가 → 당일 종가)을 다시 물으면 정확도가 samsung 0.454 → 0.564,
sk_hynix 0.499 → 0.576 로 오르고 log_loss 는 두 종목 모두 약 −0.10 (95% 월 블록 CI 상한 −0.08) 개선된다.
**이 개선의 원인은 모델이 아니다. 정답의 일부인 갭이 예측 대상에서 관측값으로 바뀌었기 때문이다.**
close_to_close = (1+gap)(1+session) − 1 이고, P09 가 보인 대로 예측력은 거의 전부 갭에 있다.
09:00 이후에는 그 갭을 **맞힐 필요가 없다 — 읽으면 된다.**

**세션 쪽에는 아무것도 더해지지 않았다.** 타깃을 세션(시가→종가)으로 바꿔 같은 비교를 하면
log_loss 차이가 samsung −0.0016 [−0.0039, +0.0010] · sk_hynix −0.0010 [−0.0022, +0.0002] 로 **둘 다 동률**이고,
세션 AUC 차이도 −0.002 / +0.002 로 0 이다. 즉 **실현 갭을 알아도 남은 장중 방향은 조금도 더 잘 맞히지 못한다.**
종가→종가에서 얻은 것은 전부 "이미 일어난 부분"이다.

**07:00 예측은 여전히 정직한 사전 예측이고, 09:37 숫자와 나란히 놓고 "모델이 좋아졌다"고 읽으면 안 된다.**
09:37 재예측은 시가에 행동하려는 사람에게는 쓸모가 없다 — 그 시점에는 이미 갭만큼 가격이 움직인 뒤다.

계획: [guides/model-improvement-plan.md](../../../../guides/model-improvement-plan.md) P16(계획 밖 등록 2026-09-20).
직접 선행: [P09 갭·세션 분해](../../P09/20260910T0700Z_gap_session_legs/decision.md),
[R02c 그룹 D](../../R02c/20260916T1200Z_group_d_direction/decision.md)의 "다음" 절이 지목한 방향.

## 채택 규칙 (결과를 보기 전에 정한 것)

1. **t0900 − t0700** 의 log_loss 95% 월 블록 CI **상한이 0 미만**이어야 한다 — 두 종목 모두, 또는 한 종목
   명확한 우위 + 다른 종목 동률.
2. 그리고 **t0900 이 모델 없는 `gap_rule` 을 log_loss 에서 이겨야** 한다. 이기지 못하면 "모델이 갭을 읽는 것
   이상을 하지 못한다"는 뜻이므로 모델을 올릴 이유가 없다.
3. 1·2 를 통과해도 채택의 의미는 **"정보 시점을 바꿀 가치가 있다"**이지 **"모델이 개선됐다"**가 아니다.
   보고서·원장 반영은 이 작업에서 하지 않는다(설계만 남긴다).

## 설정

- 기준선·폴드: P00 과 같은 계약(`No macro ensemble` 시세만, 5년 창, 2021-01 ~ 2026-09 의 6개월 12폴드,
  밴드 = 과거 20일 변동성 × 0.3, SEED 42). 노트북은 이 실행에서 **고정 스냅샷 캐시**로 다시 돌렸다
  (samsung `3d1a03863c448ec5d1aa` / sk_hynix `fa4dfc966108ea6024bb`). P00 이후 코드가 바뀌어 평가일이
  1,367 / 1,362 이고 시세만 입력이 61 / 58열이다 — R02c·P10b 와 같은 사정이며, 비교는 **모두 같은 실행 안**에서 했다.
- 후보는 **둘**뿐이다(후보를 늘리면 낙관 편향, 계획 4절).
  - `t0700` — 현행 대표 모델의 입력 그대로. 노트북이 같은 폴드로 낸 대표 모델 OOF 와
    **argmax 일치율 1.000, log_loss 차이 0.000000** — 재현이 정확하다.
  - `t0900` — 같은 입력 + **그룹 G 6열**. 행 d 가 쓰는 당일 정보는 **시가 하나뿐**이다.
    `gap_0` = open_d/close_{d−1} − 1 · `gap_over_band` = gap/밴드_d · `gap_z60` (직전 60세션 갭 분포의 z,
    평균·표준편차는 `shift(1)` 이라 d−1 까지) · `gap_abs` · `gap_up_band`(gap > 밴드) · `gap_down_band`(gap < −밴드).
    d일 종가·고가·저가·거래량은 **어느 열에도 들어가지 않는다**(테스트로 고정, 아래 "누수").
- 기준 행(후보 아님): `gap_rule` — 모델 없이 갭 부호만 읽는 규칙(갭 > 밴드 상승 / < −밴드 하락 / 나머지 보합).
  `Always flat`(사전확률), `notebook OOF (No macro ensemble)`(재현 확인용).
- 타깃: **1순위 close_to_close**(보고서가 내는 그것, 같은 밴드), **2순위 session**(진단, 밴드는 P09 규칙으로
  세션 수익률의 과거 20일 변동성 × 0.3). 두 타깃 모두 t0700 vs t0900 을 같은 폴드·같은 날짜에서 재학습했다.
- 모델·결합·온도·내부 선택 규칙은 대표 모델과 같다(`_ensemble_probabilities` = Logistic + LightGBM 확률 평균).
- 학습 시간(12폴드 합): t0700 29.6 / 29.3초, t0900 32.0 / 30.8초. 그룹 G 는 비용이 거의 없다.
- `t0900_surprise`(갭 − 모델이 예상한 갭)는 **하지 않았다.** 누수 없이 "예상 갭"을 만들려면 폴드마다 갭
  회귀 모델을 따로 학습해야 해서 싸지 않고, 후보가 셋이 되면 반복 비교 편향이 커진다. 게다가 `gap_z60`
  (최근 60세션 갭 분포 대비 놀람)이 같은 성격의 정보를 이미 담고 있다.

## 누수 — 이 실험에서 유일하게 중요한 위험

`tests/test_post_open_reforecast.py` 18개가 다음을 기계로 고정한다.

| 계약 | 테스트 |
| --- | --- |
| d일 **종가·고가·저가·거래량**을 바꿔도 행 d 의 그룹 G 는 그대로 | `test_todays_close_high_low_volume_do_not_change_todays_group_g` |
| d일 **시가**를 바꾸면 행 d 의 연속 4열이 모두 바뀌고, **그 이전 날짜는 한 칸도** 안 바뀐다 | `test_todays_open_changes_the_group_g_row_and_no_other_row` |
| d 이후 봉을 바꿔도 행 d 는 그대로 | `test_future_bars_do_not_change_earlier_rows` |
| 예측일 행은 **그날 봉의 시가**로 계산되고, 봉이 아직 없으면 앞 값을 끌어오지 않고 **결측** | `test_prediction_date_row_uses_that_days_open_and_is_missing_without_a_bar` |
| 시가 없는 날은 채우지 않고 결측 | `test_a_day_without_an_open_is_missing_not_filled` |
| z 점수는 d−1 까지의 갭만 본다 | `test_zscore_uses_only_gaps_through_the_previous_session` |
| `gap_rule` 확률은 학습 구간에서만 만든다(외부 라벨이 인자에 없다) | `test_outer_labels_cannot_change_the_probabilities` |

**하나만 예외가 있고 그것은 누수가 아니다.** d일 시가를 바꾸면 d+1 이후의 `gap_z60` 이 바뀐다 — d+1 시점에
gap_d 는 이미 과거이므로 60세션 분포에 들어가는 것이 맞다. 테스트가 "바뀌는 열은 `gap_z60` 뿐"임을 확인한다.

**제외된 날.** 봉이 없는 평가일 0일, 시가가 없는 평가일 0일. 그룹 G 결측은 전체 학습 행 중 **1행**(첫 봉,
전일 종가가 없다)뿐이고 이 행은 어느 폴드의 학습·시험 구간에도 없다 — **12폴드 전부에서 제외 학습 0 / 시험 0.**
세션 타깃은 시가 없는 봉 때문에 전체 2,753행 중 20행의 라벨이 결측이지만 역시 폴드 밖이다.
따라서 **두 후보가 완전히 같은 날짜(samsung 1,367일 / sk_hynix 1,362일)에서 채점됐다.**

확률의 argmax) 0.5333 / 0.5411 이 다르다. 규칙 방향과 조건부 argmax 가 일치하는 날이 samsung 68.5% ·
sk_hynix 63.1% 이기 때문이다(주로 보합 버킷에서 갈린다). 규칙의 정의에 충실하도록 `y_pred` 는 규칙
방향을 쓰고, log_loss·brier 에만 조건부 확률을 쓴다. 어느 쪽을 써도 위 결론은 바뀌지 않는다.

## 읽는 법 — 오해하기 쉬운 지점

1. **"정확도가 0.45 → 0.56 으로 올랐다"는 문장은 그 자체로 틀렸다.** 두 숫자는 다른 질문의 답이다.
   0.45 는 "내일 어떻게 될까", 0.56 은 "오늘 아침 이렇게 열렸는데 종가는 어떻게 될까"다.
   같은 표에 넣을 때는 **반드시 정보 마감 시각을 함께** 적는다.
2. **09:37 재예측은 시가에 행동하려는 사람에게 쓸모가 없다.** 이득의 원천인 갭은 그 시점에 이미
   가격에 들어가 있다. 09:00 에 사는 사람이 얻는 것은 "이미 오른 주식을 상승이라고 부르는 것"뿐이다.
3. **모델이 규칙을 이기는 폭은 작다.** log_loss 로만 유의하고 방향 정확도는 사실상 동률이다.
   09:37 숫자를 자랑하고 싶다면 `gap_rule` 을 같이 보여 줘야 정직하다.
4. **07:00 예측이 나빠진 것이 아니다.** t0700 은 사전확률 대비 여전히 유의하게 낫다(log_loss −0.068 / −0.078).
   P16 은 07:00 제품을 부정하지 않고, 07:00 에서 더 짜낼 것이 없다는 P03·P09·P10b·R02c 의 결론을
   **정보 시점을 바꿔서** 우회한 것이다.
5. **계획 4절대로 종목별로 판단했고** 두 종목의 결과가 같은 방향·같은 크기다. 한 종목 결과를 다른 종목에
   옮겨 적지 않았다.

## 채택

**채택 규칙 1·2를 모두 통과했다.** 그러나 규칙 3에 따라 이 작업에서는 **코드·노트북·보고서를 바꾸지 않는다.**
`forecast_utils.py` 와 노트북은 그대로이고 `forecast_history/`·`docs/` 도 건드리지 않았다.
실제 반영은 사용자가 승인하는 별도 작업이다. 아래는 그 작업을 위한 설계만이다.

### 운영 반영 설계 (구현하지 않음)

- **원장 `kind`/모델명.** 09:37 행은 **`Post-open 0937`** 이라는 별도 모델명으로 기록한다. 07:00 사전 예측
  행(대표 모델 · `Candidate expanding` · `Candidate evening open`)을 **절대 덮어쓰지 않는다.** P15 의
  `Candidate expanding` 이 쓴 방식과 같다 — 같은 `target_date`, 다른 `model`, 다른 `config_hash`.
  기존 "최초 사전 예측 보존" 규칙(`append_forecasts`)이 그대로 지켜지려면 09:37 실행이 대표 모델 이름으로
  원장을 다시 쓰지 않는 것이 유일한 조건이다.
- **채점.** `review_ledger` 가 모델별로 따로 센다. 09:37 행의 적중률을 07:00 행의 적중률과 **한 표에
  나란히 두되 "정보 마감" 열을 붙인다.** 07:00 행만이 계획 4절이 말하는 "조정하지 않은 미래 사전 예측"이다.
  09:37 행은 정보 시점이 다르므로 대표 모델 선택 근거로 쓰지 않는다.
- **보고서 문구.** 카드에는 "**09:37 갱신 — 시가(갭 x.xx%)를 반영한 값입니다. 07:00 예측과 비교해
  모델이 좋아진 것이 아니라 정보가 늘어난 것입니다.**" 를 적고, 07:00 예측을 지우지 않고 위아래로 함께 둔다.
  이미 `overnight_value_html` 이 "밤사이 미국 시장을 반영한 값"이라고 적는 것과 같은 정직 규칙이다.
  `gap_rule` 이 같은 날 무엇이라 말하는지도 한 줄 병기하면 독자가 모델의 몫을 스스로 잰다.
- **실행 위치.** `.github/workflows/afternoon-report.yml`(09:37 KST). 시가는 그 시점 일봉의 `open` 으로
  이미 들어와 있어 **새 데이터 수집이 필요 없다.** 다만 라이브 행에서 그날 봉이 아직 안 붙었으면
  그룹 G 가 결측이 되므로(테스트로 고정한 동작) **그 경우에는 09:37 행을 내지 않고 건너뛴다** —
  전일 시가를 끌어다 쓰면 그것이 바로 이 실험이 막아 둔 거짓말이다.
- **실행이 밀릴 때.** 이 워크플로의 주석이 기록하듯 GitHub cron 의 09:37 회차는 실제로 14:10 에 도착한
  날이 있었다. 그룹 G 는 **시가만** 읽으므로 늦게 돌아도 누수는 생기지 않는다(그 시점 봉의 종가가 살아
  있어도 특징에 들어가지 않는다 — 테스트로 고정). 다만 **원장·보고서에는 "09:37"이 아니라 실제 실행
  시각을 적어야** 한다. 장중 늦게 낸 예측을 개장 직후 예측인 척하면 이 실험이 막으려던 바로 그 거짓말이 된다.
- **되돌림.** 09:37 모델을 끄면 원장·보고서가 07:00 만 있던 상태로 그대로 돌아간다(추가 행만 쌓기 때문).
