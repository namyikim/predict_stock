# 자동매매 검증 및 운영 단계

사용자 목표(2026-10-04): 장기적으로 자동매매를 통해 비용 차감 후 수익을 얻는 시스템.
현재 공개 보고서는 판단 자료를 제공하고, 전략 연구·거래 평가는 관리자 실험실에서 진행한다.
수익성은 구현 완료로 입증되지 않으며, 실거래는 후속 검증과 계좌·한도 설정이 필요하다.

## 1. 평가 계산 교정 — 구현

- 개장 전 이용 가능한 방향 예측만 시가 진입에 사용. 시각 누락·개장 이후·Post-open은 제외 이유를 표시한다.
- 공식 원장처럼 2026-09-28 이후에는 KST 당일 아침 우선, 없으면 최초 기록. 저녁 후보 예외 유지.
- 예측 선택 후 결측·미채점을 보고 더 나중의 기록으로 대체하지 않는다.
- 예측 매매 / 매일 장중 보유 / 첫날 매수 후 마지막 날 매도 기준선을 분리한다.
- 정수 수량·잔여 현금·체결 금액 기준 매수/매도 수수료·매도세·슬리피지를 계산한다.
- 비용 0은 별도의 민감도 실험으로 구분한다. 기본 요율은 가정이며 사용자 계좌 요율을 보장하지 않는다.
- 브라우저와 Node 테스트가 docs/lab/trading_sim.js의 동일 엔진을 사용한다.

현재 제한: 모델마다 가용 원장 날짜가 달라 모델 간 수익률 직접 순위 비교는 하지 않는다.
보유 전략은 관측일 사이에도 보유하나, 낙폭·보유일 수는 원장 관측일에 한정한다.
배당·분할 등 기업행사, 실제 주문 체결, 호가 단위·세금 반올림은 반영하지 않는다.
현재 표시값은 선택한 규칙으로 사전 예측을 재평가한 결과이며, 사전에 동결한 전략의 실시간 운영 실적이 아니다.

## 2. 거래 구간별 전략 검증 — 시가 진입 전략의 기간 분리 구현

1. 실제 발행 시각 이후의 체결 가능한 시세를 보관한다. Post-open은 그 자료가 없으면 평가하지 않는다.
2. 장중 / 발행 이후 / 5·20거래일 보유를 별도의 전략·시점으로 정의한다.
3. 공통 거래 달력과 기업행사를 포함한 가격 계열로 평가하고, 결측 구간·기준선 가용 여부를 표시한다.
4. 학습·전략 선택·미사용 평가 기간을 분리한다. 비용 차감 수익, 낙폭, 시장 노출, 거래 횟수 및 불확실성을 비교한다.
5. 확률과 상승/하락 폭으로 계산한 기대 이익이 비용을 넘는지 검사하는 미거래 규칙을 후보로 검증한다.

수익성이 확인되지 않으면 모델·전략을 자동 승격하지 않는다. 기존 P09·P16 등의 결과와 코드부터 재사용한다.

## 3. 자동 모의운용 — 관찰용 원장 기반 구현, 장중 운영 검증 대기

- 전략 버전·비용·투자 한도를 실행 전에 동결하고 별도의 결정/주문/체결/잔고 원장에 저장한다.
- 예측 원장은 읽기 전용으로 사용하며 모의거래 결과로 예측을 덮어쓰지 않는다.
- 같은 거래일 재실행은 중복 주문을 만들지 않는다. 재시작·부분체결·취소·잔고 불일치 시나리오를 검증한다.
- 데이터 누락·지연·한도 초과·연결 장애 시 신규 주문 중지 및 관리자 알림을 구현한다.
- 종목별 한도와 삼성전자·하이닉스 합산 반도체 한도를 모두 적용한다.

## 4. 증권사 연결 및 소액 실거래 — 별도 단계

사용 증권사, 모의투자 계좌, 실제 요율, 허용 투자금·손실 한도를 정한 뒤 연결한다.
비밀키는 공개 GitHub Pages나 브라우저에 저장하지 않고 주문 서버에서만 사용한다.
모의운용과 증권사 장부 대조 검증이 끝나기 전에는 실주문을 활성화하지 않는다.
실거래 성과가 정해진 기준을 충족할 때만 사람이 규모 확대 여부를 결정한다.

## 이번 실행 기록

- 기존 작업 폴더에서 1단계를 구현했다. 주문 연결은 포함하지 않는다.
- 독립 검토에서 공식 당일 우선 원장 선택과 결측 확률 표시 문제를 발견해 수정했다.
- Node 계좌 계약 검증을 포함한 실험실/관리자 테스트 45개 통과. 모바일 375px에서 문서 폭과 스크롤 폭이 모두 375px임을 확인.
- 전체 테스트 1,688개 실행: assertion 실패 0, 로컬 의존성 누락 오류 161, 건너뜀 15. 전체 통과로 간주하지 않는다.
- 독립 재검토에서 수정된 당일 우선 정책과 결측 표시를 확인했으며 추가 중요 문제는 발견되지 않았다.
- 1단계는 사용자 요청에 따라 cd3c3beb로 커밋·푸시했다.


### 기간 분리 검증 실행(2026-10-04)

```sh
python tools/evaluate_trading.py --target samsung --config macro_inputs/trading_validation.json --out docs/lab/validation_samsung.json
python tools/evaluate_trading.py --target sk_hynix --config macro_inputs/trading_validation.json --out docs/lab/validation_sk_hynix.json
```

- 같은 날짜의 유효 예측이 있는 공통 관측일만 사용하고 모델 간 실제 시세가 다르면 중단한다.
- 후보는 선택 기간의 비용 차감 수익으로만 고른다(동률은 ID 순). 평가는 선택된 후보와 두 기준선만 수행한다.
- 각 결과는 데이터/설정/엔진 SHA-256, 생성 시각, 소스 리비전과 사용한 설정을 기록한다.
- 설정은 과거 자료를 본 뒤 지정한 예시다. 사전 등록된 미사용 평가나 앞으로의 모의운용 실적이라고 부르지 않는다.
- 기본 예시에서 선택 기간 9/7~9/18, 평가 기간 9/21~10/2. 삼성전자 9일/7일, 하이닉스 10일/7일로 모두 자료 부족.
- 최소 60일·20거래 기준은 탐색용 문턱일 뿐 수익성 인증이 아니다. 자동 승격은 항상 비활성화한다.
- 실험실에 저장 결과를 표시한다. 위 가상매매의 입력을 바꾸어도 분리 검증 설정은 바뀌지 않는다.
- 장 시작 후 체결 시세, 기업행사 포함 공통 달력, 5·20일 보유 및 자동 모의운용 원장은 아직 후속 단계다.

- 기간 분리 검증 추가 후 관련 테스트 47개 통과. 전체 1,690개 실행에서 assertion 실패 0, 기존 로컬 의존성 누락 오류 161, 건너뜀 15.
- 독립 검토에서 선택/평가 격리와 SHA 기록을 확인했으며, 브라우저에서 종목 전환 및 비용 표시를 확인했다.

### 자동 모의운용 기반(2026-10-04)

- `tools/paper_trading.py`: SQLite 트랜잭션으로 시세·최초 결정(현금 유지 포함)·주문·체결·잔고를 함께 보존한다. 재실행과 재시작이 중복 체결을 만들지 않는다.
- `macro_inputs/paper_trading.json`: 초기 가상 자금 1천만원, 종목 30%·반도체 합산 50%, 일일 손실 3%에서 신규 진입 중지. 수익성이 검증되지 않은 관찰용 `No macro ensemble` / 상승확률 > 하락확률 전략이다. 기존 원장은 설정 변경을 거부한다.
- KST 09:45 이후 처음 관측한 시세로 결정하고 **다음 실행**에서 결정 이후의 완료된 비조정 1분봉 종가로 가상 체결한다. 시세 2분 초과 지연, 주문 20분 초과, 진입가 2% 초과 변동이면 체결하지 않는다. 수수료·매도세·슬리피지를 차감한다.
- 14:30 이후 신규 진입 중지, 15:00 이후 청산 시도. 전일 미청산 보유도 다음 거래일에 청산을 시도한다. 손실 한도와 수동 중지는 신규 매수를 막으며 청산 관측은 유지한다.
- `.github/workflows/paper-trading.yml`: 평일 15분 간격 관측, XKRX 휴장일 검사, 단일 실행 그룹, 저장 전 rebase. SQLite 충돌은 덮어쓰지 않고 실패 처리한다. `paper_history/account.sqlite`가 전체 장부, `docs/lab/paper_status.json`은 최근 100건 요약이다.
- 관리자 실험실은 Pages 재배포 지연과 별개로 GitHub의 최신 요약을 읽고 관측 시각·지연·중지 사유를 표시한다. 실제 계좌·증권사 연결은 없다.

```sh
# 시세 접근·결정 없이 가상계좌만 초기화. 기존 계좌를 초기화하거나 잔고를 리셋하지 않는다.
python tools/run_paper_trading.py --initialize
# 거래일 관측 및 모의운용
python tools/run_paper_trading.py
# 네트워크·거래일 달력에 연결되지 않아도 신규 매수 중지 상태를 저장
python tools/run_paper_trading.py --halt
```

운영 판단: Yahoo 분봉과 GitHub 예약 실행은 정시성·실제 체결을 보장하지 않으므로 **지연 시 건너뛰는 관찰 실험**으로 한정했다. 시세가 계속 지연되면 체결이 0건일 수 있으며, 청산 지연으로 다음날까지 가상 보유가 남을 수 있다. 실거래 성능 검증에 사용하려면 증권사 시세·주문 피드와 별도로 대조해야 한다.

남은 단계: 실제 예약 관측의 자료 품질 확인, 거래일별 성과·노출 기록과 경보, 부분체결/주문 취소·증권사 잔고 대조, 기업행사 처리, 5·20일 보유 전략과 미거래 조건 검증. 현재 주문 모형은 정수 수량 전량 가상 체결만 지원한다.

검토 결과와 보강:
- 매도 주문 만료 후 별도 시도 ID로 재결정하고 원주문 ID를 연결했다. 재현 테스트 실패 후 수정하여 통과했다.
- 각 체결 사이에 일일 손실을 재검사해 청산 비용으로 한도를 넘긴 직후 뒤의 매수가 체결되지 않도록 했다. 재현 테스트 실패 후 수정하여 통과했다.
- push 거절은 최대 3회 rebase 후 재시도하고, 충돌은 중단한다. 실패 시 원본 SQLite·요약·설정을 30일간 아티팩트로 남긴다. 이전 실행 실패/취소 및 동일 실행 재시도는 복구 확인 없이는 다음 관측을 막는다.
- 복구 절차: 실패 실행의 `paper-recovery-*` 아티팩트와 main의 원장을 대조하고, 필요하면 보존 원장을 복원·커밋한 후 `workflow_dispatch`의 `recovery_confirmed`로 재개한다. 복구 확인은 기존 중지 상태를 해제하지 않는다.
- 중지 해제/전략 변경은 기존 장부 덮어쓰기 대신 별도 원장·전략 버전으로 운영한다. 현재 UI는 직접적인 재개·매매 버튼을 제공하지 않는다.
- 관련 테스트 69개 통과, YAML 구문·diff 공백 검사 통과. 브라우저에서 가상 자금 1천만원·체결 0건 표시와 모바일 375px 가로 넘침 없음을 확인했다. 실제 장중 Yahoo 시세·예약 실행·원격 저장 실패 복구는 운영 검증 대기다.
- 전체 테스트 1,711개 실행: assertion 실패 0, 의존성 누락 오류 161, 건너뜀 15. 이후 추가한 화면 렌더링 테스트를 포함한 관련 69개는 모두 통과했다. 전체 통과로 간주하지 않는다.
