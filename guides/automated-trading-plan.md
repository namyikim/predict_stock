# 자동매매 검증 및 운영 단계

사용자 목표(2026-10-04): 장기적으로 자동매매를 통해 비용 차감 후 수익을 얻는 시스템.
현재 공개 보고서는 판단 자료를 제공하고, 전략 연구·거래 평가는 관리자 실험실에서 진행한다.
수익성은 구현 완료로 입증되지 않으며, 실거래는 후속 검증과 계좌·한도 설정이 필요하다.

## 1. 평가 계산 교정 — 구현

- 개장 전 이용 가능한 방향 예측만 시가 진입에 사용. 시각 누락·개장 이후·Post-open은 제외 이유를 표시한다.
- 공식 원장처럼 2026-09-28 이후에는 KST 당일 아침 우선, 없으면 최초 기록. 저녁 후보 예외 유지.
- 예측 선택 후 결측·미채점을 보고 더 나중의 기록으로 대체하지 않는다.
- 예측 매매 / 매일 장중 보유 / 첫날 매수 후 마지막 날 매도 기준선을 분리한다.
- 정수 수량·잔여 현금·체결 금액 기준 매수/매도 수수료·매도세·슬리피지를 계산한다.
- 비용 0은 별도의 민감도 실험으로 구분한다. 기본 요율은 가정이며 사용자 계좌 요율을 보장하지 않는다.
- 브라우저와 Node 테스트가 docs/lab/trading_sim.js의 동일 엔진을 사용한다.

현재 제한: 모델마다 가용 원장 날짜가 달라 모델 간 수익률 직접 순위 비교는 하지 않는다.
보유 전략은 관측일 사이에도 보유하나, 낙폭·보유일 수는 원장 관측일에 한정한다.
배당·분할 등 기업행사, 실제 주문 체결, 호가 단위·세금 반올림은 반영하지 않는다.
현재 표시값은 선택한 규칙으로 사전 예측을 재평가한 결과이며, 사전에 동결한 전략의 실시간 운영 실적이 아니다.

## 2. 거래 구간별 전략 검증 — 다음 단계

1. 실제 발행 시각 이후의 체결 가능한 시세를 보관한다. Post-open은 그 자료가 없으면 평가하지 않는다.
2. 장중 / 발행 이후 / 5·20거래일 보유를 별도의 전략·시점으로 정의한다.
3. 공통 거래 달력과 기업행사를 포함한 가격 계열로 평가하고, 결측 구간·기준선 가용 여부를 표시한다.
4. 학습·전략 선택·미사용 평가 기간을 분리한다. 비용 차감 수익, 낙폭, 시장 노출, 거래 횟수 및 불확실성을 비교한다.
5. 확률과 상승/하락 폭으로 계산한 기대 이익이 비용을 넘는지 검사하는 미거래 규칙을 후보로 검증한다.

수익성이 확인되지 않으면 모델·전략을 자동 승격하지 않는다. 기존 P09·P16 등의 결과와 코드부터 재사용한다.

## 3. 자동 모의운용 — 전략 정의 및 시세 확보 후

- 전략 버전·비용·투자 한도를 실행 전에 동결하고 별도의 결정/주문/체결/잔고 원장에 저장한다.
- 예측 원장은 읽기 전용으로 사용하며 모의거래 결과로 예측을 덮어쓰지 않는다.
- 같은 거래일 재실행은 중복 주문을 만들지 않는다. 재시작·부분체결·취소·잔고 불일치 시나리오를 검증한다.
- 데이터 누락·지연·한도 초과·연결 장애 시 신규 주문 중지 및 관리자 알림을 구현한다.
- 종목별 한도와 삼성전자·하이닉스 합산 반도체 한도를 모두 적용한다.

## 4. 증권사 연결 및 소액 실거래 — 별도 단계

사용 증권사, 모의투자 계좌, 실제 요율, 허용 투자금·손실 한도를 정한 뒤 연결한다.
비밀키는 공개 GitHub Pages나 브라우저에 저장하지 않고 주문 서버에서만 사용한다.
모의운용과 증권사 장부 대조 검증이 끝나기 전에는 실주문을 활성화하지 않는다.
실거래 성과가 정해진 기준을 충족할 때만 사람이 규모 확대 여부를 결정한다.

## 이번 실행 기록

- 기존 작업 폴더에서 1단계를 구현했다. 주문 연결은 포함하지 않는다.
- 독립 검토에서 공식 당일 우선 원장 선택과 결측 확률 표시 문제를 발견해 수정했다.
- Node 계좌 계약 검증을 포함한 실험실/관리자 테스트 45개 통과. 모바일 375px에서 문서 폭과 스크롤 폭이 모두 375px임을 확인.
- 전체 테스트 1,688개 실행: assertion 실패 0, 로컬 의존성 누락 오류 161, 건너뜀 15. 전체 통과로 간주하지 않는다.
- 독립 재검토에서 수정된 당일 우선 정책과 결측 표시를 확인했으며 추가 중요 문제는 발견되지 않았다.
- 커밋·푸시는 사용자 확인 후 진행한다.
