# 자동 실행과 발행

## 워크플로 일정

| 워크플로 | KST 일정 | 역할 |
| --- | --- | --- |
| `daily-report.yml` | 평일 06:22, 07:25 및 3시간 간격 복구 회차 | 주식·보조 보고서 생성 |
| `afternoon-report.yml` | 평일 09:37 | 실제 시가로 시초가예측 채점 |
| `afternoon-report.yml` | 평일 16:10 | 실제 종가로 나머지 예측 채점 |
| `watchdog.yml` | 평일 09:20 | 최신 거래일의 사전 예측 누락 감시 |
| `monthly-longterm.yml` | 매달 7일 07:00 | 장기 전망 갱신 |
| `tests.yml` | 코드 push·PR | 전체 테스트 |
| `transformer-experiment.yml` | 수동 실행 | Transformer 비교 실험 |

`daily-report.yml`의 3시간 간격 회차는 각 기준 시각의 `:22`, `:37`, `:52`에 재시도합니다. GitHub cron이 지연되거나 누락될 수 있어 여러 기회를 두지만, 게이트가 원격 원장을 확인해 이미 처리된 작업은 몇 초 안에 건너뜁니다.

정확한 cron 표현은 항상 [워크플로 파일](../.github/workflows/)이 최종 기준입니다.

## 일일 보고서가 실행되는 방식

삼성전자와 SK하이닉스는 매트릭스의 별도 프로세스로 실행합니다. 종목별 원장과 보고서 경로가 달라 병렬로 처리할 수 있고, 업로드 충돌은 최신 SHA를 다시 읽어 재시도합니다. 한 종목이 실패해도 다른 종목은 계속 실행합니다.

06:22 본 실행에서는 종목 보고서와 무거운 보조 보고서를 처리합니다. 07:25는 장 시작 전 백업입니다. 3시간 회차는 빠른 게이트를 먼저 실행하며, 인기 급상승 검색어처럼 실제로 자주 변하는 보고서만 필요할 때 갱신합니다.

## 중복 방지

- 09:00 이전에는 해당 **예측 대상 거래일의 사전 예측**이 원장에 있는지 확인합니다.
- 09:00 이후에는 그날 처리 기록이 있으면 새 사전 예측을 만들지 않습니다.
- 다음 날짜는 평일 계산이 아니라 KRX 달력으로 구합니다.
- 게이트는 현재 체크아웃이 아닌 `origin/main`의 원장을 우선 읽습니다.
- 원격 조회 실패 시 작업 트리를 대체 경로로 사용합니다.

주말·공휴일에 월요일 또는 다음 개장일 예측이 이미 있으면 같은 예측을 다시 만들지 않습니다.

## 코드 push와 보고서 데이터 커밋

노트북·헬퍼·`tools/`·워크플로처럼 실행 코드가 `main`에 push되면 테스트 성공 후 보고서를 다시 만듭니다. 이 회차는 `PREDICT_STOCK_RECORD_FORECAST=false`라 원장에 새 공식 예측을 추가하지 않습니다.

반대로 `docs/`, `forecast_history/`, `macro_history/` 같은 결과 커밋은 경로 필터로 일일 워크플로를 다시 부르지 않습니다. 보고서가 자기 커밋을 보고 무한 반복되는 것을 막습니다.

## 시가·종가 채점

09:37에는 그날 시가만 확정된 상태이므로 `kind=open` 행만 채점합니다. 16:10에는 종가까지 확정된 행을 채점하고 기존 HTML의 `예측 vs 실제` 표시 영역만 교체합니다. 모델 전체를 다시 학습하지 않으며 새 예측도 기록하지 않습니다.

## 실패 감지

발행을 시도했는데 원장 또는 보고서 업로드가 하나라도 실패하면 자동 실행을 실패로 끝냅니다. 의도적으로 발행을 끈 실행은 `건너뜀`이며 오류가 아닙니다.

감시 작업은 평일 09:20에 가장 최근 KRX 거래일의 사전 예측이 있는지 검사합니다. 휴장일은 정상으로 처리하고 거래일 기록이 없으면 일부러 실패시켜 GitHub 알림 메일을 보냅니다.

각 보고서에는 생성 시각과 코드 커밋이 표시됩니다. 평일에 예측일이 지났는데 새 보고서가 없으면 브라우저 상단에도 오래된 보고서 경고가 나타납니다.

## GitHub Secrets

저장소 **Settings → Secrets and variables → Actions**에서 설정합니다.

| 이름 | 필요도 | 용도 |
| --- | --- | --- |
| `GITHUB_TOKEN` | 자동 제공 | 원장·보고서 커밋과 Pages 재빌드 |
| `KOSIS_API_KEY` | 주식 자동 실행 필수 | 경기·반도체 수출; strict 모드에서 없으면 실패 |
| `ECOS_API_KEY` | 선택 | 뉴스심리와 장단기 금리차 |
| `DART_API_KEY` | 선택 | 공시와 영업이익 이력 |
| `KRX_ID`, `KRX_PW` | 선택 | KRX 투자자별 수급; 없으면 다른 경로 사용 |
| `DATA_GO_KR_KEY` | 선택 | 관세청 품목별 수출 |
| `FRED_API_KEY` | 선택 | FRED 대체 시계열 |

`GITHUB_TOKEN`은 Actions가 자동으로 넣으므로 직접 만들 필요가 없습니다. 개인 토큰을 README, 노트북 또는 로그에 기록하지 마세요.

## 수동 실행

GitHub 저장소에서 **Actions → 일일 보고서 → Run workflow**를 선택하고 실행할 종목을 고릅니다. 수동 실행은 중복 게이트를 의도적으로 우회하므로 필요한 경우에만 사용합니다.

## 발행 주체와 환경 차이

공식 발행은 GitHub Actions가 담당합니다. Colab과 로컬은 기본적으로 로컬 결과만 만듭니다. 여러 환경에서 같은 원장에 쓰면 라이브러리 버전이 다른 예측이 섞일 수 있기 때문입니다.

원장에는 다음 식별자를 남깁니다.

| 열 | 의미 |
| --- | --- |
| `runtime` | `github-actions`, `colab`, `local` |
| `versions_hash` | Python·라이브러리 버전 묶음의 해시 |
| `config_hash` | 특징·밴드·모델 등 예측 설정의 해시 |

보고서는 Contents API로 커밋되며, 이후 Pages 재빌드를 명시적으로 요청합니다. `GITHUB_TOKEN`이 만든 커밋이 다른 워크플로를 자동으로 호출하지 않을 수 있기 때문입니다.

## 운영상 한계

- GitHub cron은 정시 실행을 보장하지 않습니다.
- Yahoo Finance와 일부 정부 사이트가 클라우드 IP를 차단할 수 있습니다.
- Colab과 Actions의 라이브러리 버전 차이로 같은 코드·시드에서도 수치가 달라질 수 있습니다.
- 원격 자료 실패 시 보관본을 쓰되 노후 경고와 만료 규칙을 적용합니다.
