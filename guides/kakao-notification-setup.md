# 카카오톡 본인 알림 연결 준비

2026-10-07 공식 문서 확인. **연결 방식 검토 완료 / 인증·발송 코드는 아직 미구현**.
기존 계획: [이메일 유입·카카오톡 연결](email-traffic-tracking-plan.md).

## 이번에 선택한 범위

보고서가 게시되면 운영자 본인의 카카오톡 ‘나와의 채팅’으로 회차 요약과 링크를 보낸다.
기존 이메일 수신자에게 카카오톡을 일괄 발송하거나 친구 목록을 수집하지 않는다.

| 방식 | 용도와 제약 | 이번 적용 |
| --- | --- | --- |
| 나에게 메시지 REST API | 로그인·talk_message 동의한 본인에게 발송 | 우선 구현 대상으로 선정 |
| 카카오톡 공유 | 이용자가 버튼을 눌러 대화방을 선택; 서버 예약 발송 기능이 아님 | 별도 기능 |
| 친구에게 메시지 API | 같은 서비스 이용자 간 상호작용; 친구/메시지 추가 권한 심사 등 필요 | 제외 |
| 비즈니스 알림톡 | 서비스→고객 알림 용도; 비즈니스 채널·템플릿 심사·공급사 계약/요금 확인 필요 | 구독자 전체 발송 요청 때 별도 검토 |

메시지 API의 공개 일간 쿼터는 앱 30,000건, 발신자/수신자 각 100건, 발신자-수신자 쌍 20건이다.
앱 실제 쿼터·정책은 개발자 콘솔에서 다시 확인한다. 우선 개장 전/마감 후 통합 알림 각 한 건으로
설계하고 유료 API 설정은 켜지 않는다. 알림톡의 계약별 가격은 이번에 확인하지 않았다.

## 사용자가 먼저 준비할 것

1. [카카오디벨로퍼스](https://developers.kakao.com/)에서 본인 카카오계정으로 로그인하고 앱을 만든다.
   이미 사용할 앱이 있으면 새로 만들 필요 없다. 개발자 등록·약관 동의는 본인이 수행한다.
2. 해당 앱의 **카카오 로그인**을 활성화한다.
3. **카카오 로그인 → 동의항목 → 접근권한 → 카카오톡 메시지 전송**을 설정한다.
   권한 이름은 `talk_message`. 목적은 ‘본인이 요청한 예측 보고서 요약과 링크를 나와의 채팅에 전달’이다.
4. **앱 → 제품 링크 관리 → 웹 도메인**에 `https://namyikim.github.io`를 등록한다.
   메시지 링크는 `/predict_stock/` 하위 보고서로 제한한다.
5. 앱 준비 여부만 알려준다. REST API 키, Client Secret, 인가 코드, 액세스/리프레시 토큰을
   대화·Git·화면 캡처에 붙이지 않는다. 키 설정과 로그인 연결은 인증 코드가 준비된 다음에 안내한다.

**아직 토큰을 발급하거나 시험 메시지를 보내지 않아도 된다.** 리다이렉트 URI는 Worker 인증 경로
구현·검증 후 정확한 주소를 안내한다. 존재하지 않는 콜백 주소를 먼저 등록하거나 임시 토큰을
영구 자동 발송 설정으로 사용하지 않는다.

## 다음 구현안 — 검토 대상

### 인증과 비밀값

- 현재 단일 파일 Worker 수동 배포 방식을 유지한다. REST API 키·Client Secret·토큰 암호화 키는
  Cloudflare Secrets에 보관한다. 카카오 인가·토큰 요청은 공식 엔드포인트만 사용한다.
- 관리자 인증을 거친 연결 시작에서 일회용 state를 발급하고, 짧은 만료·브라우저 세션 결합·재사용 거부를 적용한다.
  STATS_TOKEN은 URL/인가 state에 넣지 않는다. 콜백에서 state·앱·연결 대상 확인을 마친 뒤 토큰을 저장한다.
- 액세스/리프레시 토큰은 서버 저장소에 암호화해 보관한다. 갱신 응답에 새 refresh_token이 없으면
  기존 값을 유지하고, 있으면 교체한다. 동시 갱신을 제어하며 만료/동의 철회 시 재연결 상태를 표시한다.
- 관리자 응답·예외 로그에는 토큰과 인가 코드 원문을 내보내지 않는다. 연결 해제는 전송 중지와
  서버 토큰 폐기를 수행하며 카카오 연결 해제 API의 영향도 따로 안내한다.

### 발송과 중복 방지

- 게시 검증을 마친 기존 mail_events의 보고서 내용을 읽되, 이메일 발송 성공이나 구독자 존재를
  카카오 발송 조건으로 삼지 않는다. 별도 카카오 제어·발송 원장을 둔다.
- 회차일/개장 전·마감 후/연결 버전별 유일 키로 한 회차를 한 번만 접수한다. 이메일 일시 중지와
  카카오 일시 중지는 구분하고, 카카오 기본값은 꺼짐이다.
- 기본 텍스트 템플릿과 `POST https://kapi.kakao.com/v2/api/talk/memo/default/send`를 사용한다.
  날짜·회차·삼성전자/SK하이닉스의 실제 보고서 요약·전체 보고서 링크를 포함한다.
- 길이 제한과 허용 링크를 검사한다. 성공 응답 `result_code=0`은 API 전송 성공으로 기록하며
  수신자의 열람으로 표시하지 않는다. 재시도 중복 방지 기능이 있다고 가정하지 않는다.
- 시간 초과 등 실제 전송 여부가 불명확하면 자동 재발송하지 않고 확인 필요로 표시한다.
  인증 갱신·권한 부족·쿼터·확정 거절은 구분하고 카카오 실패가 이메일을 막지 않도록 분리한다.

### 관리자와 방문 집계

- 연결/만료/재연결 필요, 최근 시도·전송 성공·실패·확인 필요, 중지/재개 표시.
- 카카오 유입은 `utm_source=kakao`로 이메일과 분리한다. 수신자 식별값 없이 보고서/회차만 전달한다.
  기존 이메일 파서·통계 호환을 유지하며 카카오 내부 브라우저의 표시도 검증한다.
