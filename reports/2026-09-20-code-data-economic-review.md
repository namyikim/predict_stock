## 우선 수정할 문제

### 1. [P1] 장기 예측의 보정/평가 경계에 미래 정보가 들어간다 — 확신 10/10

위치: `tools/build_longterm_report.py:243–248`, `evaluate`.

```python
half = n // 2
slope = float(np.clip(np.sum(pp[:half] * yy[:half]) / denom, 0., 1.))
err_model = np.abs(yy[half:] - slope * pp[half:])
```

워크포워드 학습에는 h개월 제한이 있지만, 그 뒤 예측값을 보정하는 단계는 단순히 앞/뒤 절반으로 나눈다. 앞 절반 마지막 행의 12개월 수익률은 뒤 절반 평가가 시작된 뒤에야 확정된다. 이 값을 기울기 계산에 사용하므로 최종 평가가 완전히 시점 외 검증이 아니다.

재현: 평가 시작 2005-01-31, 보정 마지막 행 2004-12-31, 해당 정답 확정 2005-12-31. 이 정답만 변경했는데 보정 기울기가 0.2000에서 0.3467로 변했다. 미래 정보가 평가에 적용될 보정계수를 바꾼다.

개선: 보정 행의 실제 `target_date`가 평가 시작 시점까지 확정된 행만 사용한다. 결측 월이 있을 수 있으므로 단순 행 수보다 달력 기준 만기일 비교가 안전하다. 동일 검사를 가격·분기 모델의 보정과 모델 선택 경계에도 적용한다. 수정 후 장기 성적과 발행 게이트를 다시 계산해야 한다.

### 2. [P2] 수출 단가·물량을 충분히 받아도 잘못된 분모 때문에 제외한다 — 확신 10/10

위치: `tools/build_earnings_forecast.py:1254`.

```python
price_active = all(c in f.columns and f[c].notna().mean() > 0.5 for c in UNIT_PRICE_FEATURES)
```

특징의 충족률을 실제 이익 학습 가능 기간이 아닌 전체 수출 프레임에서 계산한다. 수출은 2005년부터, 단가·중량은 2015년부터 받도록 되어 있어 오래된 빈 구간이 분모에 들어간다.

재현: 수출 2005-01~2026-09, 단가·물량 2015-01~2026-08(140개월), 이익 2016년 이후로 구성했다. 전체 분기 기준 충족률은 48.3%라 탈락하지만 기본 모델 학습 가능 분기에서는 97.4%다.

실제 저장된 삼성전자·하이닉스 `earnings.json`도 `quantity_info.enabled=true`, `rows=140`인데 `price_active=false`다. 저장 보고서의 원시 단가 프레임은 없어 그 실행의 정확한 결측 분포까지 복원하지는 않았지만, 동일 현상을 만드는 코드 결함은 재현했다.

개선: 공통 학습 가능 분기·최소 유효 표본·라이브 행 유효성으로 후보의 평가 가능 여부를 판정한다. 이 변경은 후보 검증을 가능하게 하는 것이며 자동으로 대표 모델에 채택하라는 뜻은 아니다.

### 3. [P2] 수출 단가·물량의 보관 경로가 연결되지 않았다 — 확신 10/10

위치: `tools/build_earnings_forecast.py:1025`, `1142–1184`, `main`의 발행 구간.

- 읽기는 `fallback_dir / "customs_quantity.csv"`를 기대한다.
- 성공한 다운로드는 `out_dir / "customs_quantity.csv"`에 저장한다.
- 초기 원격 보관본 목록에 `customs_quantity.csv`가 없다.
- `--publish`에서도 이 파일을 올리는 처리가 없다.
- 캐시 읽기마저 `if key:` 안에 있어 키가 없으면 보관본만으로 이어갈 수 없다.

따라서 주석의 ‘처음 한 번 전체 이력 수집, 이후 최근 18개월만 갱신’ 경로가 일반 실행에서는 성립하지 않는다. 반복 실행마다 긴 이력을 다시 조회하고 장애 시 대체 데이터가 사라진다.

개선: 기존 캐시 파일 하나를 읽기·쓰기의 공통 경로로 사용하고, 다른 관세청 자료처럼 원격 보관·복원에 포함한다. 키 유무는 새 조회만 제어해야 한다.

### 4. [P1, 모형 품질] 영업이익 80% 구간의 실측 포함률이 28.6%다 — 확신 10/10

근거: `docs/samsung/earnings.json:69`, `docs/sk_hynix/earnings.json:69`; 구간 계산은 `tools/build_earnings_forecast.py:531–569`, `1346`.

두 종목 모두 저장된 현재 분기 모델의 평가 결과가 14분기 중 4분기 포함, 즉 28.6%다. 표본이 작아 장기적인 진짜 포함률을 확정할 수는 없지만, 명목 80%와의 차이는 크다. 보고서는 이미 이를 경고한다. 따라서 숨긴 오류가 아니라 개선이 필요한 모형 품질 문제다.

또한 저장 보고서는 9월 10일치 수출 속보로 9월 전체 수출을 추정한 뒤 `months_used=3`으로 처리한다. 학습은 과거 확정 월자료로 하고 라이브 입력은 부분월 추정값을 쓰는데, 그 추가 오차가 과거 잔차 구간에 별도로 반영되지 않는다. 이 부분월 추정이 낮은 과거 포함률의 원인이라고 단정할 수는 없지만 라이브 불확실성을 추가한다.

개선:

1. 확정월 수와 잠정월/관측일 수를 구분한다. 10일·20일·월말 정보 집합별로 같은 시점의 과거 자료를 재현한다.
2. 최근 시점에서 확정된 잔차만으로 순차 보정하고, 완만한 국면과 급증·적자전환 국면의 포함률을 따로 보고한다.
3. 수출 속보→월말 추정의 오차까지 실적 예측구간에 반영한다.
4. 우위 판정은 MAE가 두 기준선보다 단지 작은지뿐 아니라 같은 분기의 오차 차이와 불확실성도 보고한다.

### 5. [P2] 경제지표 장애가 대표 방향 모델을 다른 모델로 바꾼다 — 확신 9/10

위치: 노트북 코드 셀 20·34·38. 파일 줄 `8091`, `11258`, `13050`.

‘시세만’ 모델 학습은 `if MACRO_ACTIVE:` 안에 있다. 월별 경제지표가 꺼졌는데 뉴스심리·수급은 살아 있는 경우에도 해당 모델 자체가 생성되지 않는다. 대표 선택 코드는 `No macro ensemble`이 없으면 `Mean ensemble`로 대체하므로 뉴스심리·수급이 포함된 다른 모델이 대표가 된다.

Actions는 `MACRO_STRICT=true`라 일부 장애에서 먼저 중단하지만, 기본 Colab·로컬 실행 또는 `--no-macro` 경로에는 영향이 있다. 현재 정상 운영이 항상 잘못됐다는 뜻은 아니다.

개선: 시세만 대표 모델은 경제자료의 존재 여부와 무관하게 만든다. 입력 열 목록이 전체 모델과 동일할 때만 계산 결과를 재사용한다. 보고서에 요청한 모델과 실제 발행 모델을 모두 기록한다.

### 6. [P2] 오래된 해외 수익률이 새로운 일일 정보처럼 반복된다 — 확신 10/10

위치: 노트북 셀 15, `merge_latest_available`와 `.ffill(limit=5)`; 파일 줄 `6986`, `7099`.

해외 자산의 ‘수익률’을 최근 값으로 as-of 연결한다. 미국 휴장일에는 직전 거래일의 수익률이 다음 한국 거래일에도 그대로 반복된다. 이후 특징 전체에 수행하는 전방 채우기는 `safe_pct_change`가 공백 때문에 비워둔 값도 다시 채울 수 있다. 라이브 결측 경고 이전에 채워지므로 대체 여부가 감춰질 수 있다.

재현: 2026-09-04 미국 수익률 +3%를 입력하면 9월 7일과 8일 한국 행에 모두 +3%가 들어간다.

개선: 가격 수준의 마지막 값과 새 수익률을 분리한다. 직전 한국 예측 시각 이후의 누적 해외 수익률, `new_session`, 마지막 관측 시각을 사용하거나, 마지막 미국 거래 수익률을 계속 쓸 의도라면 그 나이를 명시적 특징으로 둔다. 미국 휴장과 API 실패를 같은 0%로 처리해서도 안 된다.

### 7. [P2] 보조 자료 결측이 시세만 모델의 표본도 제거한다 — 확신 9/10

위치: 노트북 셀 15·20, 파일 줄 `7219`, `8061`.

```python
model_df = feat.loc[sam.index, feature_cols + NON_FEATURE_COLS].dropna()
market_X = X[:, market_feature_idx]
```

먼저 전체 특징의 완전 관측 행만 남기고 그 뒤 시세 열을 분리한다. 따라서 대표 모델에서 쓰지 않는 뉴스심리·수급의 결측도 대표 모델의 학습 데이터를 줄인다. 같은 날짜로 성능을 비교하는 것은 맞지만, 모든 모델의 학습 표본까지 보조 자료에 종속시킬 필요는 없다.

개선: 모델별 입력으로 학습 가능 행을 만들고 평가 결과만 공통 날짜에서 비교한다. 대표 모델의 행 수·마지막 학습일이 선택 자료를 켜고 끄는 것만으로 달라지는 회귀 검사를 추가한다.

### 8. [P2] 영업이익 특징 추가 비교가 동일 분기를 보장하지 않는다 — 확신 9/10

위치: `tools/build_earnings_forecast.py:1257–1267`.

기본 모델 전체의 MAE와 `FEATURES + UNIT_PRICE_FEATURES` 또는 `FEATURES + TSMC_FEATURES`의 MAE를 각각 계산해 비교한다. `walk_forward`가 필요한 열별로 `dropna`하므로 평가 분기가 달라질 수 있다. 후보가 어려운 분기를 제외하기만 해도 더 좋아 보일 수 있다. 현재 후보 일부는 꺼져 있으므로 주로 활성화 이후의 위험이다.

개선: 두 OOF 결과를 분기 인덱스로 inner join하여 동일 실제값에 대한 오차 차이를 계산한다. 표본 수·공통 기간을 표시하고, 모델 선택과 최종 평가는 분리한다.

### 9. [P2] VXN은 문서와 달리 방향 예측에도 들어간다 — 확신 10/10

노트북 셀 11의 주석은 VXN을 ‘방향 특징이 아니라 구간 폭에 사용’한다고 설명하지만 `GLOBAL_ASSETS`에 포함되어 셀 15에서 `vxn_ret_1`, `vxn_ret_5`가 생성된다. 시세만 모델에서도 제외하지 않는다. 저장된 2026-09-20 삼성전자 실행 설정에서 두 열을 확인했다.

VXN의 방향 특징 사용 자체가 반드시 나쁜 것은 아니다. 문제는 ‘구간만 바꾼 실험’으로 생각해도 방향 모델의 입력이 함께 바뀐다는 점이다. 방향 포함을 별도 실험으로 명시하거나, 의도대로 구간 전용으로 분리해야 한다.

### 10. [P2] 분기 앞 k개월 계산은 달력상의 앞 k개월을 보장하지 않는다 — 확신 10/10

위치: `tools/build_earnings_forecast.py:415–423`.

관측 행의 `cumcount()`로 순서를 매기므로 1월이 누락된 2·3월 자료에 k=2를 주면 이를 ‘앞 2개월’로 사용한다. 실제 함수 호출로 평균 2.5가 반환됨을 확인했다.

개선: 월별 정규 인덱스로 먼저 맞추고 분기 내 달 번호를 사용한다. 누락 월을 건너뛰어 같은 k를 만족한 것으로 취급하면 안 된다.

| DRAM 현물가 | 로컬 보관본 8일, 표시·누적용 | 이 표본으로 학습하지 않는 판단은 적절 |
| DART 공시·미국 주요 일정 | 공시 표시, 이벤트 표식, 실적 채점 | 방향 특징 누락 버그로 볼 근거 없음 |
| 영업 레버리지 항 | 후보 비교만 수행, 공식 실적 수치는 기본 FEATURES 사용 | 삼성 개선·하이닉스 악화로 종목별 검증 필요 |
| 검색어·위키 관심도·AI 뉴스·중국·거시 설명 보고서 | 독립 보고서 경로이며 주식 대표 모델의 자동 입력 아님 | 표시 데이터와 학습 데이터를 화면에서 구분 |

레버리지 후보의 저장 MAE: 삼성 4.107조→3.737조로 약 9% 감소, 하이닉스 1.694조→1.718조로 약 1.4% 증가. 이 숫자만으로 즉시 채택할 근거는 부족하다.

기존 P03 실험도 추가 특징군이 일관되게 개선하지 못했다. ‘데이터를 받고 있으니 모두 넣어야 한다’는 방향은 권하지 않는다. 특히 P03의 월별 효과로 표시된 `Mean ensemble` 대 `No macro ensemble` 비교는 정의상 NSI·수급도 함께 제거하므로 순수 월별 지표 효과와 묶음 효과를 구분해 해석해야 한다.

## 경제·금융 관점의 개선

### 반도체 가격과 물량의 정의부터 바로잡기

`data_sources/exports.py:597`은 수출액/중량을 단가로 계산한다. 이는 달러/kg이며 DRAM ASP(칩·bit당 평균판매가격)가 아니다. HS 8541·8542 안의 품목·패키징·고부가 제품 비중 변화만으로도 상승한다. ‘가격 상승분이 거의 그대로 이익’이라는 보고서 설명도 제품 구성, 원가, 환율·헤지 차이를 지나치게 단순화한다.

IMF 역시 이질적인 품목의 구성 변화가 무역 단위가치와 순수 가격 변화를 혼동시킬 수 있다고 설명한다. 이름을 ‘수출 단위중량당 금액’으로 명확히 하고, 가능하면 메모리별 가격·bit 출하·제품 구성 지표와 나란히 확인한다. [IMF 무역가격지수 매뉴얼](https://www.elibrary.imf.org/abstract/book/9781589067806/ch02.xml)

### 삼성전자와 하이닉스의 이익 구조를 분리하기

현재 두 회사 모두 국가 반도체 수출과 연결 영업이익의 관계를 주로 학습한다. 삼성전자는 DS뿐 아니라 DX·디스플레이 등 다른 사업이 있어 수출 하나로 전체 이익을 설명하는 데 한계가 있다. 삼성 공식 실적 자료도 사업부별 실적을 구분해 제공한다. [삼성전자 공식 실적 자료](https://www.samsung.com/global/ir/financial-information/earnings-release/)

개선 후보는 삼성 DS/기타 사업의 분리 추정, 하이닉스의 DRAM·NAND·HBM 제품 구성, 재고·감가상각·설비투자 변화다. 그러나 분기 표본이 적으므로 처음부터 다변량 모형으로 늘리지 말고 가장 설명력이 있는 변수 1~2개씩만 동일 분기에서 검증한다. 수익성 변화와 주가 수익률 예측의 성공 여부도 별도로 평가한다.

### 경기 수준보다 정보의 변화와 기대 차이를 검증하기

주가는 이미 알려진 경기 수준보다 새 정보에 반응할 수 있다. 수출 증가율만큼 발표 전 기대 대비 차이, 이익 전망 수정, 산업 재고 전환 등이 연구 후보가 된다. 현재 코드의 ‘야간 가격에 반영되므로 미국 발표 결과를 중복 투입하지 않는다’는 선택은 합리적인 출발점이지만, 한계효과가 항상 0이라는 증명은 아니다.

컨센서스의 당시 판본과 실제 발표 시각을 확보할 수 있을 때만 서프라이즈 특징을 검증한다. 사후 수정된 기대치로 과거 서프라이즈를 만들면 안 된다. 데이터 접근성과 효과가 검증되기 전 대규모 수집부터 시작하지 않는다.

### 발표 지연과 수정치 문제를 따로 해결하기

월+2 지연은 발표 전 값 사용을 완화하지만, 현재의 수정된 과거 숫자를 당시 알았던 값으로 바꾸지는 못한다. 저장된 `cli_g20_vintages.csv`가 있어도 실제 `cli_features`는 기본 `month,value` 자료를 사용한다. CLI는 경기 전환점 지표이며 주가 예측 지표와 동일하지 않다. OECD는 월별 수정과 과거 판본 자료를 명시적으로 제공한다. [OECD CLI FAQ](https://www.oecd.org/en/data/insights/data-explainers/2024/04/composite-leading-indicators-frequently-asked-questions.html)

실적도 `profit.shift(1)`만으로 직전 분기가 이미 발표됐다고 가정하지 말고 실제 공시일로 제한해야 한다. 특히 분기 첫 달의 잠정 수출을 조기에 쓰는 경로에서는 직전 분기 확정 실적이 아직 없을 수 있다. 현재 k=3 저장 보고서에서 실제 누수가 발생했다고 확인한 것은 아니며, 조기 나우캐스트 경로를 고칠 때 필요한 시점 조건이다.

TSMC는 최근 스냅샷을 매달 기다리는 것 외에 공식 과거 월매출 페이지가 있다. 연속 이력 확보가 지금 보관된 5개 관측치를 활용하는 가장 직접적인 개선이다. 공시 시각과 단위를 함께 보존해야 한다. [TSMC 2020년 공식 월매출](https://investor.tsmc.com/english/monthly-revenue/2020)

## 실행 속도 개선 순서

1. **매일 예측과 과거 전체 평가를 분리한다.** `tools/run_notebook.py`는 모든 코드 셀을 매번 실행한다. 여러 제외 모델의 내부 그리드 탐색·전체 외부 폴드·신뢰구간까지 반복한다. 우선 확정 과거 폴드의 결과를 코드·설정·해당 입력 스냅샷으로 캐시하고, 당일 학습·발행 경로는 유지한다. 재학습 주기를 바꾸는 것은 예측 방법 변경이므로 별도 검증 대상이다.
2. **부트스트랩의 행별 손실을 미리 계산한다.** 노트북 `paired_delta_ci`는 반복마다 DataFrame 슬라이스와 `log_loss`를 다시 수행한다. 행별 두 모델의 음의 로그확률 차이를 한 번 만들고 같은 월 블록 인덱스의 평균을 구하면 계산을 줄일 수 있다. 동일 클리핑·정규화와 같은 난수 추출로 기존 결과와의 일치를 검증한다. 불균형 정확도 등 비선형 지표는 단순 평균으로 대체하지 않는다.
3. **두 종목의 공통 다운로드를 재사용한다.** SOX·Nasdaq·환율·KOSIS 등을 같은 실행에서 중복 조회한다. 먼저 단가·물량의 잘못된 전체 재조회부터 제거하고, 이후 같은 시각에 수집된 공통 스냅샷을 종목별 계산에 전달한다. 최신 조회 실패를 오래된 캐시로 조용히 덮어서는 안 된다.
4. **학습 입력 열 목록이 동일한 제외 모델은 재사용한다.** 선택 자료가 꺼진 상태에서 같은 모델을 여러 이름으로 재학습할 필요가 없다. 모델 계열·입력 열·학습 인덱스·설정이 같은 경우만 재사용한다.

이는 코드 구조에서 확인한 비용 절감 후보다. 실행 전체 프로파일링이나 변경 전후 속도 측정은 하지 않았으므로 몇 배 빨라진다는 수치는 제시하지 않는다. GPU 확대·Transformer 재도입은 우선순위가 낮다. 기존 실험에서 이득이 확인되지 않았고 현재 반복 계산 비용부터 줄이는 편이 타당하다.
